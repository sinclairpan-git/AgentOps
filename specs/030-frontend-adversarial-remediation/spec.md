# 功能规格：前端对抗评审问题归档与修复

**功能编号**：`030-frontend-adversarial-remediation`  
**创建日期**：2026-05-08  
**状态**：执行中  
**输入**：归档两个前端对抗评审视角发现的问题，并依次修复 AgentOps Console 前端体验、布局、空态、搜索和视觉质量问题。修复完成后重新进行业务小白与 Web 测试专家对抗复测。

## 范围

本工作项覆盖 `apps/agentops-console` 前端实现和配套前端契约测试。目标是把当前“只读治理报告页集合”推进为更像成熟控制台的可用工作台：每页有清晰结论、可理解空态、可靠搜索反馈、稳定排版和明确下一步。

不覆盖后端真实生产 IAM、数据库、多租户、外部 Agent Store HTTP 联调、真实审批写操作、真实 Outbox replay 或真实凭证签发。本阶段仍保持只读治理控制台边界。

## 对抗评审归档

### 业务小白视角

- 控制台专业可信，但新用户不知道下一步该做什么。
- 页面术语过重，`verified_loaded`、`L5`、`Grant`、`DLQ`、`Outbox` 等默认暴露。
- 空数据页缺少“为什么为空、是否正常、如何产生数据、谁负责”。
- 全局搜索输入后没有结果面板或无结果反馈。
- 风险处置页从总览跳转后断流，缺少队列、负责人和下一步动作。

### Web 测试专家视角

- 证据检索页存在 `<data-table>` 未注册 Vue error。
- Ai_AutoSDLC 页存在长文本、条件串、表格列挤压和潜在重叠。
- 顶部标题区域过窄，多页中文标题硬换行。
- 多个表格只显示表头，缺少统一空态。
- 状态徽标语义混杂，配置、健康、风险、流程状态未分层。

## 用户故事与测试

### 用户故事 1：小白用户可以理解当前页面结论（P0）

作为首次进入 AgentOps Console 的业务用户，我希望每个页面都能告诉我当前是否需要处理、下一步是什么，以便不用先理解内部术语。

**独立测试**：逐页进入 11 个导航页面，首屏必须存在页面结论或高质量空态，且不能只剩表头或大片空白。

### 用户故事 2：操作入口不会断流（P0）

作为使用总览入口的用户，我希望点击“风险队列”“治理证明”等入口后，目标页能承接上下文，以便知道为什么跳转、该看哪里、该做什么。

**独立测试**：点击总览 CTA、全局搜索结果、通知/待办和风险处置详情，目标页或抽屉必须有明确内容或安全空态。

### 用户故事 3：专业测试者可以确认页面布局稳定（P0）

作为 Web 测试专家，我希望所有页面在桌面和移动宽度下没有文字重叠、硬裁切、关键字段不可读或组件注册错误。

**独立测试**：桌面和移动视口逐页截图，浏览器 console 无 Vue error；长 ID、条件串、表格列可读或可横向滚动。

## 需求

- **FR-001**：证据检索页必须注册并渲染 `DataTable`，浏览器 console 不得出现 `<data-table>` 未注册错误。
- **FR-002**：全局搜索必须展示结果面板；无命中时必须展示“未找到”反馈；结果必须能跳转到对应页面。
- **FR-003**：风险处置页必须展示队列或高质量空态，包含来源、严重度、负责人、下一步动作和详情入口。
- **FR-004**：所有表格型页面必须有统一空态，不得只显示表头。
- **FR-005**：Ai_AutoSDLC、连接器、凭证等长文本页面必须避免重叠和不可读裁切。
- **FR-006**：完整数据来源 banner 仅在总览页展示，功能页仅保留顶部简短状态。
- **FR-007**：顶部标题区域必须避免常见中文导航标题硬换行。
- **FR-008**：每页必须提供面向非技术用户的简短结论或下一步提示。
- **FR-009**：状态徽标必须保持现有契约兼容，同时减少同屏语义混杂造成的误读。

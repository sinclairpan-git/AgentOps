# 规格：Console 处置审计时间线

**功能编号**：`010-console-audit-timeline`

**依赖**：`009-console-triage-action-detail`

## 目标

承接 009 的只读处置详情，把“建议怎么处置”推进到“这条处置链路发生了什么、还卡在哪里、审计包能否被安全复核”。Console 必须在处置详情内展示时间线、责任触点、审计包摘要和回显目标，帮助管理员判断下一步，而不执行生产写操作。

## 范围

- `actionWorkbench.details` 中每条处置详情必须包含 `timeline` 和 `audit_packet`。
- 时间线必须展示至少三个只读节点：发现/建模、待处理或已处理状态、关闭条件。
- 审计包摘要必须包含包 ID、摘要、证据引用、回显目标、导出状态和安全说明。
- 前端处置详情抽屉必须用中文展示“处置时间线”和“审计包摘要”。
- 契约测试必须禁止 `raw_payload`，并确保没有真实下载链接、原文访问链接或生产写动作。

## 非目标

- 不执行审批通过/拒绝、Grant 签发、风险关闭、通知发送或 Agent Store 写回。
- 不生成真实文件下载，不暴露 Evidence Vault 原文，不接入生产 IAM/RBAC。
- 不把 AI-SDLC adapter 的 `materialized/unverified` 解释为 `verified_loaded`。

## 验收标准

- AO10-CT-001：每个处置详情都有可展示的中文时间线，节点包含阶段、时间、说明、负责人、状态。
- AO10-CT-002：每个处置详情都有审计包摘要，且只包含摘要、哈希/引用和回显目标，不含 `raw_payload` 或下载 URL。
- AO10-CT-003：Agent Store gap、证据失败、审批待办三类详情都能生成时间线和审计包摘要。
- AO10-CT-004：前端处置抽屉必须展示“处置时间线”“审计包摘要”“导出状态”“回显目标”“只读复核包”。
- AO10-CT-005：schema 校验必须拒绝缺少时间线或审计包摘要的后端快照。
